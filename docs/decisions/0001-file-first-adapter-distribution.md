# ADR-0001：文件优先与 adapter 分发

- 状态：Accepted
- 日期：2026-07-23

## 背景

本机同时使用 Claude Code 与 Codex。两端都支持规则、Skills、Agents、Hooks 和 MCP，但加载路径、配置格式和部分元数据不同。后续还需要把资产放到网盘、NAS、Git 或移动介质，在新设备上直接恢复。

PromptHub 已经覆盖资产浏览、Skill 分发、版本历史和备份，但其内部数据库、平台预设和快照格式不应成为个人资产的唯一事实源。

## 决策

采用以下结构：

1. 人可读的纯文本资产目录是唯一事实源。
2. Core 只处理 manifest、Profile、依赖、校验和构建，不直接修改用户目录。
3. Claude Code、Codex 和未来工具由独立 adapter 生成目标文件。
4. SQLite 仅用于可重建的搜索索引和 UI 状态。
5. 网盘保存不可变、带 manifest 和 SHA-256 的资产包，不实时同步数据库。
6. 密钥只保存引用，真实值由设备侧 Secret Provider 解析。
7. PromptHub 作为产品参考或可选 UI，不作为运行时依赖。
8. 首版独立实现；若未来复用 AGPL 代码，则重新评估许可证和发布方式。

## 原因

- 文件可以直接 diff、review、Git 版本化和手工恢复。
- adapter 能显式处理平台差异，避免“同一个文件复制到所有目录”造成静默失效。
- 不依赖特定 UI 或数据库后，更换 AI 工具、设备和同步介质的成本更低。
- 不可变资产包比共享可写数据库更容易校验、回滚和排查。

## 影响

正面影响：

- 资产格式长期稳定；
- 新设备部署可重复；
- 敏感数据边界清楚；
- PromptHub 或未来 UI 可以被替换。

代价：

- 必须维护平台 adapter 和兼容测试；
- 平台新增字段不能只修改公共 schema；
- UI 中的编辑最终要落回纯文本文件；
- 原生会话和自动记忆不能承诺无损跨工具迁移。

## 不采用的方案

### 直接维护 PromptHub 私有 Fork

技术上可行，但会承担上游合并、AGPL 边界、内部数据库兼容和平台预设漂移的长期成本。

### 只用网盘同步工具目录

工具目录混有密钥、缓存、会话、数据库、绝对路径和设备状态，不适合作为可移植资产。

### 所有平台共用完全相同文件

Claude Code 与 Codex 的规则文件、agent、hook 和 MCP 格式不同，逐字共享会把兼容问题推迟到运行时。
