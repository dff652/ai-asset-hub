## 2. 历史与文件树边界

`main` 与 `dev` 使用 squash PR，当前提交图为 main 独有 16、dev 独有 35。候选从
`origin/main` 建立，然后精确带入 `origin/dev@89b4492` 的最终文件树差异。这样既
保留 main 的发布治理，也避免把分叉提交历史误写成用户 changelog。

候选提交、main 合并与发布后 dev 同步必须分别证明文件树：

```bash
git diff --check
git diff --name-status origin/dev <candidate-head>
# 只允许本候选检查点及其索引/状态文档有额外差异
# main 合并、发布后文档收口完成后：
git diff --quiet origin/dev origin/main
```

不得移动或重写 `v0.1.8`；它仍如实指向原 dev 发布提交。`v0.1.9` 必须是新的
annotated tag，并且 peel 后精确等于通过 CI 的 `origin/main` SHA。
