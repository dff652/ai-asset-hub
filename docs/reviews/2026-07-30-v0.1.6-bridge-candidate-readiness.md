## 1. 为什么这是 bridge release

`v0.1.5` 已发布二进制不能追溯修复。它在 `v0.1.6` 成为 latest Release 后仍会生成
不含 `AIAH_VERSION` 的 legacy 命令：

```text
curl -fsSL https://raw.githubusercontent.com/dff652/ai-asset-hub/v0.1.6/scripts/install.sh | sh
```

按 staged-pin 规则，`v0.1.6` tag 内安装器默认版本必须继续指向已经验收的
`v0.1.5`。因此复制上面的旧命令会保持在 `v0.1.5`；这不是新修复失效，而是旧二进制
和不可变 tag 共同形成的一次性兼容边界。

本次发布必须：

1. 逐字记录 `v0.1.5` 实际生成的 legacy 命令；
2. 在隔离目录执行并确认它保持 `v0.1.5`；
3. 在 Release 说明中公开该边界和显式版本 workaround；
4. 使用 `AIAH_VERSION=0.1.6` 完成真实升级；
5. 保留 installer 默认 pin 为 `v0.1.5`，直到 `v0.1.6` 发布后验收完成。

`v0.1.6` 二进制已经包含修复后的命令生成逻辑。只有将来
`v0.1.6 → v0.1.7` 时，才能首次要求程序实际输出：

```text
.../v0.1.7/scripts/install.sh | AIAH_VERSION=0.1.7 sh
```

并把“推荐命令端到端闭环”标记为通过。
