## 2. 分支历史边界

仓库只允许 squash PR。`main` 与 `dev` 在 v0.1.6 发布后已经同步到相同文件树，
但不会互为祖先；直接用 `dev → main` 会把已经发布的提交重新列入 PR，并产生大量
无意义冲突。

本候选因此从 `origin/main` 建立 `release/v0.1.7`，再带入
`dev@a0ff294` 的**最终文件树差异**。发布 PR 的内容来源仍是已验收 `dev`，但 PR
只展示 `main` 真正尚未拥有的 tree delta。候选提交前必须证明：

```bash
git diff --check
git diff --stat origin/main
```

发布后仍按发版 SOP 把已验收 `main` 文件树同步回 `dev`；不得声称 squash 后
`main` 已成为 `dev` 的祖先。
