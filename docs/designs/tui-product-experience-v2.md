# TUI 产品体验与导航方案 V2

- 状态：**Accepted；Phase E1/E2/E3.1 已随 `v0.1.6` 正式验收，E3.2 已在当前
  开发分支实现并进入候选验证，尚未发布**
- 日期：2026-07-29
- 关联：[TUI 技术方案](tui-technical-design.md)、
  [ADR-0006](../decisions/0006-tui-as-first-interactive-surface.md)、
  [上手指南](../getting-started.md)
- 取代范围：取代旧方案中面向用户的首页、术语和“必须理解
  `compose → build → diff → apply`”的交互表达；Core、安全边界和 CLI 契约不变

## 0. 决策摘要

1. 产品定位为 **面向多 AI 工具与多设备的 AI 编程资产管理器**，不是知识库；
   跨工具整合和换机迁移是核心使用结果。
2. 面向用户统一使用“资产库”，`workspace` 只保留在 CLI、契约和开发语境。
3. `aiah` 在交互 TTY 中直接启动 TUI；`aiah ui` 保持兼容。
4. TUI 以任务首页启动，不再把 inventory 树作为新用户看到的第一屏。
5. 面向首次使用者的完整流程表达为：

   ```text
   发现资产 → 整理资产库 → 检查并准备 → 预览变化 → 人工确认
   ```

   前四步不写目标工具目录，只有第五步完整输入 `apply` 后才写入并创建安装恢复点。
   `validate` 和 `build` 仍由同一 Core 执行，但日常界面只把它们显示为
   “检查资产、准备安装包”；跨设备场景再明确使用“生成分发包”。安装检查与撤销
   是应用后的安全闭环，不额外增加一条需要记忆的主流程。
6. 人工操作最终都可进入 TUI；CLI 全部保留给脚本、CI、MCP 和高级操作，不以
   TUI 覆盖为由删除或改变 JSON 契约。
7. 设置只允许保存非业务 UI 偏好；资产、资产组合、目标工具和安全策略仍以
   `manifest.yaml` 为事实源。

## 1. 产品定位：资产管理，不是知识库

一句话定位：

> 把散落在 Claude、Codex、Grok 等 AI 编程工具中的 skills、rules、agents、
> hooks 和 MCP 模板整理成一份可版本管理的资产库，并安全地预览、安装、检查、
> 撤销，以及迁移到新工具或新设备。

选择“资产管理”的理由：

- 当前核心对象是带类型、目标工具、作用域、敏感级别、依赖、哈希和版本的**可执行/
  可配置资产**，不是以文章为中心的知识条目；
- 核心业务是扫描、归档、校验、确定性打包、adapter 转换、安装、备份、漂移检查和
  回滚，属于资产生命周期；
- skill、rules 和 memory 可能承载知识，但只是资产类型的一部分；
- 当前没有文章创作、全文/语义检索、问答、引用关系、RAG、权限发布或知识运营等
  知识库核心能力。

[IBM 对知识管理的概述](https://www.ibm.com/think/topics/knowledge-management)和
[Atlassian 对知识库的定义](https://www.atlassian.com/itsm/knowledge-management/what-is-a-knowledge-base)
都把重点放在组织知识的集中存储、检索、分享与自助获取。将 aiah 称为知识库会让
用户期待搜索问答、语义检索和内容编辑，并弱化本项目最有区别度的 adapter、安装
安全和回滚能力。

因此：

- 产品：**AI 编程资产管理器**；
- 工作区：**资产库**；
- `memory`、说明文档等可以称为“知识型资产”；
- 未来若增加全文/语义检索，也作为资产发现能力，而不改变当前产品主定位。

## 2. 外部流程与用语调研

本方案参考的是业务流程，不复制代码或视觉实现。

### 2.1 chezmoi：源状态、diff、apply

[chezmoi Quick Start](https://www.chezmoi.io/quick-start/) 把 dotfiles 管理表达为
`init → add → edit → diff → apply`，并明确区分 source state 与 home 目标状态。
这与 aiah 的资产库和工具目标目录最接近。

采用：

- “加入资产库”比“写出”清楚；
- 修改目标前先展示变化；
- “应用”比“部署”更贴近日常本机配置；
- 跨设备仍基于可版本管理的源状态。

不采用：

- aiah 不隐藏多目标 adapter、敏感信息和回滚边界；
- 不自动替用户提交或推送 Git。

### 2.2 lazygit、K9s：主命令直接进入 TUI

[lazygit](https://github.com/jesseduffield/lazygit#usage) 和
[K9s](https://k9scli.io/topics/commands/) 都允许直接运行主命令进入交互界面，
复杂操作仍保留 CLI 参数、命令模式或快捷键。

采用：

- `aiah` 直接进入 TUI；
- `?` 随时显示当前页面可用操作；
- 首页先显示状态和用户任务，详情页再显示工程字段。

### 2.3 ansible-navigator：欢迎页与 CLI/TUI 双入口

[ansible-navigator subcommands](https://docs.ansible.com/projects/navigator/subcommands/)
同时提供 welcome、inventory、settings、run 等交互入口，且保留对应 CLI 命令。

采用：

- 首页按用户任务分组，而不是把全部子命令平铺；
- TUI 与 CLI 是同一 Core 的两种入口；
- 设置与业务事实分离。

## 3. 信息架构

### 3.1 首页

```text
AI 编程资产管理器
统一管理 Claude、Codex、Grok 的 skills、rules 与 agents

资产库：未选择
资产状态：发现 7 项 · 1 个风险与问题
当前安装：正在检查…

> 整理本机资产        发现并加入统一资产库
  预览并应用资产库    检查、准备安装包并预览变化
  安装检查与撤销      检查漂移，必要时撤销上次安装
  迁移到其他设备      比较资产库、当前安装与分发通道
  关于与更新          查看当前版本并手动检查 Release
```

后续阶段再加入：

```text
  跨设备分发          生成、发布、查看或取回不可变版本
  设置                语言和默认/最近资产库
```

未实现的入口不得显示成可操作菜单。

首页进入后并行执行只读资产扫描和安装检查。选择资产库后，“资产状态”改为统一展示
未纳管、已纳管、待更新、仅库内、不可纳管和本机问题计数；“当前安装”展示安装包、
版本、目标工具和健康结论。用户不需要先进入设置或手动触发检查，才能看到这些
必要状态。

### 3.1.1 状态信息分层

状态采用渐进披露，但不能用“界面简洁”隐藏做决定所需的信息：

| 层级 | 必须显示的信息 | 位置 |
|---|---|---|
| 全局摘要 | 当前资产库路径、统一资产计数、不可纳管/扫描问题、当前安装包与版本、目标工具、健康结论 | 首页，默认可见 |
| 操作上下文 | 当前资产组合、包路径/版本、目标工具、create/update/skip 数量、风险与问题、确认词 | 变更预览与确认页，写入前可见 |
| 恢复与迁移 | `backupId`、rollback 可用性、资产库/安装/通道路径与版本、SHA256、冲突或不可比较原因 | 成功页、安装检查、迁移页 |
| 技术详情 | logical path、finding code、adapter/portability/sensitivity、逐文件 diff | 详情页或展开区 |

其中路径、版本、目标工具、风险、变更数量、确认词和恢复信息属于安全/决策信息，
始终可见且不可通过 Settings 关闭。显示密度只能决定技术详情默认展开还是折叠。

### 3.2 首次整理

```text
1 选择资产库
2 选择本机资产
3 加入资产库
4 预览并应用
```

- 可以建议 `~/ai-assets`，但必须由用户明确确认后才创建；
- inventory 退居“本机资产”页面；
- 资产行优先显示类型、来源工具和目标工具；portability/sensitivity 等放详情；
- 已有文件仍 create-only，失败仍整单回滚。

### 3.3 预览并应用

```text
选择资产组合
→ 检查资产
→ 准备安装包
→ 展示变更预览
→ 用户确认应用
```

- 只有一个 profile 时默认选中，但仍展示资产组合名称；
- `build` 是内部必要步骤，不是日常用户必须学习的业务概念；
- typed `apply` 保留为高风险写入确认词，但界面动作名称是“确认应用”；
- 成功页显示目标工具、文件数量、backupId、安装检查和“撤销本次安装”。

### 3.4 统一资产状态与管理动作

“本机 AI 资产”把扫描结果和资产库清单合成一个状态视图：

| 状态 | 含义 | 可用动作 |
|---|---|---|
| 未纳管 | 源端存在，资产库尚未登记 | 纳入 |
| 已纳管 | 源端与资产库内容一致 | 移出 |
| 源端有更新 | 源端与资产库副本不同 | 更新或移出 |
| 仅在资产库 | 已登记，但本机未发现对应源端 | 移出 |
| 不可纳管 | secret、device scope 或无法安全映射 | 查看原因 |

`更新` 是**显式用源端完整替换资产库副本**，不是后台同步；`移出` 删除资产库正文和
manifest/profile 引用，但不删除源端工具文件。两者均调用 Workspace Core、要求输入
`update` / `remove`，验证失败恢复操作前状态。成功后连续进入“选择资产组合 →
检查并准备安装包 → 变更预览”；真正写工具目录仍需另行输入 `apply`。

### 3.5 “备份 / 恢复点 / 分发”边界

- **安装恢复点**：apply 覆盖目标文件前写入 `.aiah/backups` 的设备本地材料，只用于
  `rollback` 撤销一次安装；不是资产库备份。
- **资产库备份**：必须能保留历史版本、独立恢复并验证恢复结果。当前交给私有 Git、
  NAS 快照或用户选择的备份工具，aiah 尚未提供该能力。
- **跨设备分发**：`publish / versions / pull` 发布和取回不可变包；不是双向同步，
  不传播可变工作树的修改或删除，也不解决冲突。

因此用户界面不得把安装恢复点简称为“资产备份”，也不得把不可变分发称为“同步”。

## 4. 术语表

| Core / CLI | TUI 主文案 | 说明 |
|---|---|---|
| inventory | 本机 AI 资产 | 来自各工具目录的扫描结果 |
| workspace | 资产库 | 跨工具统一、可编辑、可进 Git 的事实源 |
| candidate | 可加入 | 可安全整理进资产库 |
| compose / 写出 | 加入资产库 | 复制资产并登记清单 |
| validate | 检查资产 | schema、路径、secret、依赖等 |
| build | 准备安装包 | 日常自动步骤 |
| build（分发） | 生成分发包 | 跨设备页面的显式操作 |
| profile | 资产组合 | 一组准备一起应用的资产 |
| targets | 目标工具 | Claude、Codex、Grok |
| diff | 变更预览 | 尚未写目标目录 |
| apply | 确认应用 | 原子写入并创建安装恢复点 |
| deployment | 当前安装 | 最近一次受管应用状态 |
| doctor | 安装检查 | journal、backup、drift、MCP 前置检查 |
| rollback | 撤销上次安装 | 只针对明确的 backup |
| finding | 风险与问题 | 保留 Core code 供排障 |
| scope | 使用范围 | 全局、项目、仅本机 |

CLI 命令名和 JSON 字段不改名，避免破坏自动化契约。

## 5. CLI 与 TUI 边界

| CLI 能力 | TUI 归属 |
|---|---|
| scan | 整理本机资产 |
| validate / build | 预览并应用中的自动步骤；高级详情可单独运行 |
| diff / apply | 变更预览与确认应用 |
| doctor / rollback | 安装检查与撤销 |
| publish / pull / versions / bootstrap | 跨设备分发 |
| version / update --check | 关于与更新 |
| mcp / JSON output | 只保留 CLI，不做交互菜单 |

CLI 不会被“收缩”：

- 所有现有子命令与 JSON 输出继续兼容；
- README 首页只要求普通用户记住 `aiah`、`aiah update --check`、
  `aiah version` 和 `aiah help`；
- 其余命令移到自动化/高级参考，不隐藏、不废弃。

## 6. `aiah` 默认启动规则

```text
aiah        交互 TTY：启动任务首页
aiah ui     与上面等价，保持兼容
aiah <cmd>  原有 CLI 行为不变
```

非 TTY、空 `TERM` 或 `TERM=dumb` 时：

- 不创建资产库；
- 不进入 alternate screen；
- 输出简短帮助并非零退出；
- 脚本必须继续显式使用 CLI 子命令和 `--output json`。

二进制名称继续使用 `aiah`。更短的通用名称会降低可搜索性，改名还会影响安装器、
Release、文档与脚本；默认直接启动已经消除了记忆 `ui` 的主要负担。

## 7. 设置与语言边界

当前版本没有真正的设置页，也没有中英文切换；TUI 是中文主界面并混有工程英文。

计划中的设置只包含：

- 语言：自动、简体中文、English；
- 默认资产库和最近使用的资产库列表；
- 显示密度：标准、详细；
- 技术字段默认折叠或展开。

Settings 采用“偏好设置”定位，不承担运行状态看板。即使用户选择“标准”密度，
首页和写入确认页仍必须展示第 3.1.1 节定义的安全/决策信息。

禁止进入设置：

- assets、profile、targets、scope 等业务事实；
- secret、凭据或 MCP 实际值；
- 关闭校验、关闭备份、绕过确认；
- 隐藏资产库/目标路径、版本、目标工具、风险、变更数量、确认词或恢复信息；
- 隐式联网或自动升级。

若引入 `~/.config/aiah/config.yaml`，必须满足：

- 仅在用户明确保存设置后创建；
- schema/version 明确，权限为 `0600`，原子写入，拒绝符号链接；
- 不包含 secret；
- `manifest.yaml` 继续是所有资产业务配置的唯一事实源。

这不是 ADR-0006 所禁止的“TUI 私有业务配置”：它只保存 UI 偏好。实施前需同步修订
ADR-0006 的绝对措辞并增加安全测试。

- [x] README / getting-started 同步。

### E2：流程简化

- [x] 扫描结果与 manifest 合成统一资产状态；
- [x] 显式“纳入 / 更新 / 移出”动作及 typed confirmation；
- [x] 写操作失败恢复资产库原状态；
- [x] “纳入 / 更新 / 移出 → 选择资产组合 → 变更预览”的连续向导；
- [x] 单 profile 默认选择；
- [x] build 降为“检查资产、准备安装包”进度；
- [x] 应用成功摘要汇总目标工具、文件结果、安装恢复点和下一步。

### E3：跨设备迁移与版本对齐

- [x] E3.1 只读展示资产库、当前安装和通道最近发布版本；
- [x] 通道路径由用户明确输入，只读且不创建目录；
- [x] 对比资产库、通道和当前安装版本；
- [x] E3.2 `publish`：选择资产组合、复用 build Core、显示目标通道和包路径，
  完整输入 `publish` 后才写入不可变通道；
- [x] E3.2 `versions` / `pull`：显示同一资产库的全部发布坐标，不比较版本号大小，
  用户必须明确选择版本/profile 和已有输出目录；
- [x] E3.2 连续取回：pull 只写显式输出目录；E3.4 候选在成功后先绑定
  name/version/profile/SHA256 做目标设备检查，再由用户按 Enter 进入现有 diff 与
  typed `apply`；不新增 `--yes` 或 TUI 私有部署逻辑；
- [x] pull 输出冲突 fail-closed：完整同内容四件套幂等，残缺或不同内容拒绝且
  不覆盖；
- [x] E3.3 `e 换机检查`：选择资产组合后零写入检查 device-private、secret
  可用性、目标支持、adapter dropped/degraded，并提供完整可导航明细；
- [x] E3.4 候选：取回包检查结果来源明确为 package；坐标/SHA 不匹配或存在阻止项
  时不能进入 diff；双设备、显式旧版本恢复、中断恢复与恶意通道均有夹具；
- [x] 不接管 Git、rsync、U 盘等传输层。

- [ ] 简体中文和 English 的 golden tests；
- [ ] 标准/详细显示密度仅影响技术详情，不得隐藏安全/决策信息；
- [ ] 业务配置仍只来自 manifest。

## 9. 验收标准

- 新用户启动后第一屏能回答“工具做什么、当前状态、下一步做什么”；
- 首页自动完成只读资产扫描与安装检查，必要状态不依赖手动刷新或 Settings；
- 首次整理不要求理解 workspace、compose、build、diff；
- 所有目标目录写入前仍有只读变更预览和 typed confirmation；
- TUI 不复制 Core 业务规则，不 shell out；
- `aiah ui`、所有现有 CLI 子命令和 JSON schema 保持兼容；
- 非 TTY 默认启动不产生写入或阻塞；
- 不把未实现的跨设备或双语能力写成已完成；
- 完整本地门禁和假 HOME 闭环通过。
